# Email collected by Stripe during checkout

- **Target File / Component:** `Account.jsx`, `EmailTrialAccount.jsx`, `StripeCheckoutReturn.jsx`, `checkoutIntent.mjs`, billing routes and new `guestCheckout.js`; shared/public bilingual legal notices and release marker.
- **Deep User Experience Impact (Pros & Cons):** Choose Monthly or Annual to open Stripe without entering an email in Immigra. Stripe collects the email and payment details. Returning creates new limited device access only after server verification of payment, or asks to verify an existing account after payment. Already signed-in users keep their existing checkout. The email-only seven-day trial remains separate. A pending public checkout reference can be resumed on the device for seven days. Closing checkout without returning delays activation until recovery; users must not purchase again to recover.
- **Root-Cause Architectural Failure:** Registration and checkout creation were coupled in `openCheckout`; choosing a plan forced a local email form before opening Stripe. Removing that requirement needs a secure post-payment ownership contract, not a public unauthenticated entitlement grant.
- **Production-Grade Implementation:** Unauthenticated web-only checkout accepts only a server-priced monthly/annual plan. Server-generated flow/nonce metadata and a signed `__Host-` Secure HttpOnly SameSite=Lax 24-hour cookie bind a guest return to its browser. Payment and subscription are fetched from Stripe server-side. The public return URL alone grants nothing; no email, account ID, price or customer ID from the client is trusted. Verify completed/paid state, product, nonce, customer and owner before binding. New access reuses the existing email-only cookie service; existing private accounts require a secure sign-in link after payment. A verified owner with the same paid email can recover on another device without the cookie. Subscription/session metadata binding is retryable; a deterministic deduplicated entitlement event is older than any subsequent Stripe webhook, including events in the creation second. Portal/export/deletion remain verified-only. Current generic billing rate limits also cover the new endpoints. No new migration, secret or package is required.

## Operations and remaining limitations

Live `/api/billing/status` still reports `ready:false` and failed account/monthly/annual lookups (safe reference `req_Vy7wCGjrZMk8iL` before release). The prior safe diagnostic identified a Stripe permission error. This code change does not fix the configured API key or prove that live checkout works. Review the live account/key permissions in Render/Stripe: Account/Prices read, Checkout Sessions read/write, Subscriptions read/write, and Billing Portal Sessions write for verified management. Do not share secrets in chat. After correcting access, verify test-mode checkout, first activation, renewal, cancellation, refund and existing-account recovery before claiming payment readiness.

Guest account creation/linking runs on verified return, not on an unbound webhook. If the browser closes, use “I started a purchase · check payment” on the same device; after 24 hours, verify the paid email. When the reference is unavailable (another device, storage cleared, or more than seven days), support must recover the Stripe Checkout reference from the paid transaction and direct the verified owner through the return flow. Keep Stripe receipts/support available. A customer buying as a guest with an email that already has another active subscription can pay before Immigra knows that email; the return stops overwriting the existing entitlement and directs the buyer to support for duplicate-charge resolution. Signed-in checkout prevents this before purchase. Do not tell an already-paid customer to buy again.

No native store purchases were enabled. Static native/store checks do not replace physical-device or store review testing. Public checkout references in localStorage are not authentication credentials; their seven-day retention does not extend the trial or bypass verified ownership.
