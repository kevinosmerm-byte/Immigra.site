### 🧠 Advanced AI Brain Diagnostic Ledger

* **Target File / Component:** EmailTrialAccount, AccountSheet/AccountProvider, checkoutIntent, billing routes and read-only Stripe readiness.
* **Deep User Experience Impact (Pros & Cons):** Plan selection now visibly marks the selected option, reveals and focuses email verification, and explains the next step. Verified checkout shows an opening status instead of an apparently inert button. A subscription still requires a verified identity and Stripe payment confirmation.
* **Root-Cause Architectural Failure:** Unverified plan buttons only changed local form state without moving focus or the viewport. The selected interval lived only in sessionStorage, so opening the verification link in another tab/browser lost the purchase intention. Verified purchase buttons did not show a pending label. Errors were reduced to a generic message.
* **Production-Grade Implementation:** Non-secret, email-bound plan intent expires after 30 minutes and survives tabs; the verification return URL carries only an allowlisted interval for device-independent recovery. Intent is consumed before opening checkout. Unknown intervals are rejected, and an expired/mismatched stored intent cannot downgrade to legacy storage. Existing verification and backend ownership checks remain intact. Stripe failures map to safe bilingual categories and optional provider request references, without logging credentials or raw provider messages. Existing active subscriptions offer management rather than another purchase. Invalid email links are now visible in the email-first account screen. Checkout requests have a bounded wait.

The new GET /api/billing/status performs cached read-only Stripe requests: account charge readiness and live, active recurring monthly/annual prices matching the advertised currency and amounts. It never creates a customer, subscription or payment session, and returns only readiness categories and a safe request reference. Requests share an in-flight check and cache success for five minutes/failure for one minute. Insufficient permission to inspect provider status is reported as unverified status, not proof that checkout cannot work.
